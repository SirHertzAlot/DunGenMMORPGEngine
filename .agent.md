  agent when making design, scaffolding, or refactoring changes that affect
  services, APIs, and core domain logic. It prioritizes small, well-tested
  incremental changes and observable, instrumented code.

    - read_file

rules:
  - Keep changes minimal and focused: one logical concern per PR/patch.
  - All new behavior must include unit tests (xUnit) and, where appropriate, integration tests.
  - Follow SOLID: prefer small single-responsibility classes, explicit interfaces, and dependency injection.
  - Separation of Concerns: domain, persistence, messaging, and presentation layers must be separate.
  - Prefer composition over inheritance for game components and behaviors.
  - Always add Prometheus metrics for throughput, latency, error counts on services that process traffic.
  - For any queue consumer: prefetch=1 for strict FIFO processing of action queues; log each action with a unique id and timestamp.
  - When modifying `docker-compose.yml`, add healthchecks and clear version removal (modern Compose v2+ format) and document any new ports or persistent volumes.
  - Do not change public APIs (gRPC, HTTP, message schemas) without creating a compatibility migration plan and tests.
checklist:
  - [ ] New code has unit tests and passes locally.
  - [ ] Public interfaces have minimal, versioned changes.
  - [ ] Docker images are buildable via `docker compose build <service>`.
  - [ ] Metrics instrumentation added for new runtime components.
  - [ ] README updated for any dev-run steps.

whenToPick:
